# 密封夹（FolderSeal）用户体验检查清单

检查日期：2026-11-27。对象：当前工作区最新本地待发布构建（v2.13.0+），版本依据见 [CHANGELOG](../CHANGELOG.md) 顶部与 [安装定义](../installer/FolderSeal.nsi) 的 `VERSION`。本清单不代表 GitHub 已发布版本或本机已安装版本的验收结果。

适用角色：首次使用者、日常编辑者、处理异常的资料所有者。核心任务：创建并导入 → 打开与编辑 → 保存并锁定；辅助任务：找回位置、恢复工作区、备份、删除与升级。

本次已阅读当前源码、使用说明、安全边界、安装说明和界面测试定义，完成静态检查；未启动软件进行交互走查，未重跑测试，未执行安装、删除或异常中断实验。下列勾选框均留待实际验收，不能根据源码存在相应逻辑直接勾选通过。

## 使用方法与判定

- 只使用生成的样例资料，在隔离的测试账户或虚拟机内操作；禁止使用个人资料。崩溃、改密中断、磁盘不足、删除及卸载场景必须隔离。
- 每项完成后记录“通过 / 不通过 / 阻塞 / 不适用”，只有通过才勾选。不适用要写原因，未执行保持空白。
- 记录实际程序版本、安装包来源、Windows 版本、显示缩放、权限、样例规模、操作结果和截图或日志。证据放在 `artifacts/ux-review/`，公开前去除个人信息。
- 表内等级表示该项失败时的建议严重度，不代表已经发现相应缺陷。P0：数据丢失、错误安全状态或核心任务阻断；P1：关键任务明显受阻或关键认知错误；P2：可完成但存在文案、布局和操作瑕疵；P3：效率优化。
- 建议发布门槛：P0 全部通过；P1 不通过项有明确处理结论；未验项目单列，不用历史测试结果替代本次验收。

## 当前已有的体验保护

源码中已具备以下设计，实际效果仍需按清单验收：

1. 普通启动直接进入首页；查看加密文件夹列表时才验证密码，兼顾进入速度与列表隐私。
2. 保存失败与“密文已保存、明文清理未完成”使用不同提示和重试动作，避免把未完成清理误认为已安全锁定。
3. 删除前确认并再次验证密码；未锁定时不能执行删除或恢复，菜单说明前置条件。
4. 帮助集中提供异常恢复、备份和保护范围；后台升级检测失败不打断本地操作。

依据：[源码](../src/FolderSeal.cs) 中 `EnsureMaster`、`RefreshState`、`LockVault`、`DeleteVault`、`CreateHelpDialog`、`CheckForUpdates`。

## 静态阅读已发现的核对事项

以下为本次文件阅读得到的具体发现，不是交互测试结论。改进建议不代表新增功能已立项；后续若决定改代码，仍进入现有需求池流程。

| 对应项 | 建议等级 | 已观察证据 | 用户影响与建议 |
| --- | --- | --- | --- |
| UX-03、47 | P2 | README 的“当前本地迭代版本”落后于安装定义和变更记录顶部 | 用户难以确认是否拿到最新版。发版前统一版本说明，并核对程序实际显示版本 |
| UX-10、47 | P1 | 使用说明“导入、编辑与锁定”第 1 步把列表与手动选择并列后写“已接入的文件夹无需再次输入密码”；同页开头及源码要求手动选择独立验证 | 容易误解为手动选择也免验证。将免重复验证限定为“本次运行已验证列表后，从列表打开” |
| UX-47 | P2 | 使用说明“安装与启动”仍建议便携版放到稳定位置后“再创建文件夹图标入口”；当前界面菜单仅提供恢复与删除，已有快捷入口兼容保留 | 用户可能寻找不存在的创建入口。明确现有入口的兼容范围，并删除或改写无对应界面的操作指引 |
