# 密封夹（FolderSeal）

普通启动直接进入首页，不弹密码框、不展示列表或自动扫描。每次进入“我的加密文件夹”都需要验证密码，在同一次列表操作里选中资料打开时无需再输一次。关闭列表、完成操作后授权结束。保存并锁定后再解锁，需要重新验证。

密封夹（FolderSeal）— 你的文件，只有你能打开。

中文名：**密封夹**；英文名：**FolderSeal**。对外文档统一使用“密封夹（FolderSeal）”。程序文件名、安装包名与数据路径沿用 FolderSeal。

在本机 NTFS 磁盘中创建加密文件夹，用一个密码打开所有加密文件夹、编辑并保存，通过 Windows 文件权限限制常规删除。作者：**EurekaGao**。当前本地迭代版本见 [变更记录](CHANGELOG.md)。

程序使用 C#、Windows Forms 和 .NET Framework，在本机处理文件。没有联网找回密码功能。当前为自用工具开源版，**尚未经过独立安全审计**。请先用副本验证，并保留独立备份。

## 功能

- 同一 Windows 用户会话内只保留一个主窗口；重复启动会唤回已有窗口，资料入口转交给它处理。
- 首次后台扫描本机固定磁盘并记住加密文件夹位置，以后直接显示保存的列表，支持重新扫描和指定位置扫描。
- 按访问操作验证密码；查看列表后从列表打开不重复验证，创建和外部入口仍独立验证，旧文件夹首次输入原密码后接入。
- 解锁后打开临时编辑区，用原有编辑器查看、修改文件。
- 导入文件和文件夹；普通导入保留源文件。
- 保存时生成并核验新的加密快照，保留上一版本，再清理明文编辑区。
- 识别并恢复异常退出后遗留的工作区。
- 删除加密文件夹前再次验证密码；限制普通用户直接删除、覆盖密文。
- 兼容已有文件夹图标快捷方式，独立验证密码后打开对应资料。

## 运行环境

| 项目 | 要求 |
| --- | --- |
| 系统 | Windows 10 / 11 |
| 运行时 | .NET Framework 4.7.2 或更新版本 |
| 存储 | 本机 NTFS 磁盘 |
| 权限 | 安装及每次运行程序均需要管理员授权 |
| 编译 | Windows 自带的 .NET Framework C# 编译器 |
| 脚本 | Windows PowerShell 5.1 或 PowerShell 7 |
| 安装包构建 | 另行准备 NSIS；构建基线为 3.13 |

不支持网络共享、符号链接、目录联接、硬链接和未下载的云端占位文件。主要用于同一 Windows 管理员账户，不提供跨用户权限迁移工具。路径过长或不安全的文件名会被拒绝。

## 从源码开始

本地便携包可通过 `scripts/package-portable.ps1` 生成。使用时先解压整个压缩包到稳定位置，再运行 `FolderSeal.exe`，仍需管理员授权。包内提供中文说明和安全边界；源文件与样例验证程序不包含在便携包中。

取得本仓库后，在仓库根目录打开 PowerShell：

```powershell
.\scripts\build.ps1
Start-Process -FilePath '.\artifacts\bin\FolderSeal.exe' -Verb RunAs
```

如果脚本被执行策略阻止，可在本次进程内运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build.ps1
```

脚本使用固定源码和仓库相对路径，不下载依赖。程序、核心验证和入口验证的 EXE 位于被 Git 忽略的 `artifacts/bin/`。没有管理员权限时，程序不会执行文件夹保护操作。

源码编译产物属于便携程序。请先放到稳定位置，保持程序位置稳定，保证已有快捷入口正常使用。

## 日常使用

1. **创建**：首次设置密码至少需要 8 个字符，建议使用密码管理器生成独立长密码。已有密码仍可使用。点击“创建加密文件夹”，选择上级目录、填写名称，使用验证过的密码。
2. **导入**：使用“导入文件”“导入文件夹”，或打开编辑区后放入资料。普通导入保留原文件。
3. **编辑**：在“我的加密文件夹”中选中资料，点击打开；旧文件夹首次需输入原密码并完成接入。点击“打开所在文件夹”，用自己的软件编辑。
4. **锁定**：关闭占用文件的编辑器，点击“保存并锁定”。看到“已锁定”才表示保存与明文清理均完成。
5. **删除**：先锁定，再在“更多”中选择“删除加密文件夹…”，确认并再次输入密码。此操作永久删除，不进入回收站。

关闭资源管理器窗口不会自动锁定。正常退出时，程序会要求先保存并锁定；保存失败时保留工作区并阻止正常退出。

## 检测升级

左下角提供“检测升级”。每次启动在后台自动检测一次；发现新版后，入口显示“发现新版”和版本号，点击可确认打开浏览器下载安装包。无新版或启动检测网络失败时不弹窗；手动检测会显示结果或失败提示，不影响本地加密和编辑。

检测来源为本项目公开的 GitHub Release，包含已公开的预发布版并明确标注，只提示版本号更高且安装包已上传完成的版本。仅在本地生成、未上传的安装包不会被其他电脑发现。检测只读取公开版本信息，不上传文件、文件夹路径或密码；不自动运行安装包。安装前先保存并锁定、正常退出软件。

## 文件夹图标入口

新建或右键加密后，原位置显示同名的密封夹图标，真实密文目录隐藏。双击图标并验证密码后进入编辑区。已有资料锁定后，可在“更多”里逐个创建或修复入口。

## 资源管理器右键加密

在程序“更多”中选择“添加到资源管理器右键菜单”，之后可以不解锁主界面，直接在资源管理器里加密：

1. 右键文件或文件夹，选择“加密此文件（密封夹）”或“加密此文件夹（密封夹）”。
2. 输入密码。程序先加密并锁定内容，再删除原位置的明文。
3. 单个文件变成去掉扩展名的同名文件夹（如“季度报表.docx”变成“季度报表”）；文件夹在原位置直接变成加密文件夹。

已加密的文件夹可以右键选择“用密封夹打开”；对它再次选择“加密”只会打开，不会重复加密。菜单指向当前程序位置，移动或重装程序后需要重新添加，也可在同处移除。每次右键都会请求管理员授权。加密文件夹锁定后，普通程序无法删除、改名或移动它，删除必须在程序中验证密码；位置不受上级目录权限限制，桌面、文档、下载都可以。管理员仍可手动修改权限或接管文件，格式化、系统还原和磁盘故障不在保护范围内。

## 本机检索与统一密码

首次进入“我的加密文件夹”自动扫描所有已就绪的本机 NTFS 固定磁盘。扫描只检查文件名及文件头，真正打开时再验证完整密文。列表优先显示最近成功解锁的文件夹，支持搜索、取消扫描、重新扫描与选择位置扫描。知道确切位置时，可用“按路径打开”粘贴路径或浏览。

扫描结果加密保存在 `%LOCALAPPDATA%\EurekaGao\FolderSeal\catalog.egcatalog`。以后通过验证打开列表时直接显示记录，只检查已记录位置，不自动全盘扫描。新建或手动打开的文件夹自动加入列表。取消扫描会记住已发现结果；无权限、链接、占位文件及断开的磁盘会被跳过或标为不可用，不保证覆盖不可访问的位置。

扫描和缓存列表排除回收站、开发验证生成的样例目录。升级后验证密码时会自动清理旧缓存中的这些条目，只移除列表记录，保留磁盘上的数据；真实旧目录即使尚未统一密码也会保留。

旧文件夹首次接入时验证原密码，将当前快照与目录内的“上一版本”改用当前密码，保持各自内容。完成后原密码失效；其他位置的历史副本和备份不会自动改密，仍需各自原密码。改密中断后，用同一密码再次打开该目录恢复；不要删除 `.pending-*` 事务文件，也不要用旧程序打开迁移中的目录。

密码不以明文写入磁盘。访问操作结束后释放密码引用和已加载的目录表，编辑中只使用当前资料的派生密钥。遗失位置记录后仍可用同一密码打开已接入的目录并重新扫描。忘记密码无法恢复。

- 快捷方式不是数据本体，删除快捷方式不会删除密文。
- **备份必须包含隐藏的密文目录**，只备份快捷方式无法恢复资料。
- 已有入口绑定原程序路径。移动便携程序后如果入口失效，请进入“我的加密文件夹”，从列表选择资料，或点“按路径打开”。
- 程序仅修复指向同一资料的密封夹入口。同名项目冲突或入口失效时，可从程序中选择真实密文目录继续访问。

## 备份与异常恢复

加密目录中的主要文件：

| 文件 | 作用 |
| --- | --- |
| `内容.egvault` | 当前加密快照，包含文件内容、名称和目录结构 |
| `上一版本.egvault` | 上次成功保存的加密快照，可能包含已删除或修改前的内容 |
| `.access.lock` | 防止多个会话同时编辑的锁文件 |

锁定后用具备管理员权限的备份工具复制整个加密目录，并单独保管密码。普通权限的程序无法列出、读取、覆盖或删除密文。解锁时外部编辑器从临时编辑区访问明文。不要手动往密文目录中添加资料或直接改写密文文件。

断电、系统崩溃或强制结束进程可能留下明文：

```text
%LOCALAPPDATA%\EurekaGao\FolderSeal\Sessions\随机编号\编辑区
```

重新启动程序，选择对应加密目录，在“更多”中打开“恢复未锁定工作区”，按时间和状态选择记录，验证后核对内容并保存锁定。若来源版本不同或旧版工作区没有来源记录，程序会保留当前密文和旧工作区。按提示从旧编辑区复制所需文件，导入另一个加密文件夹，核对后保存并锁定。

保存失败后先关闭编辑器，再重试锁定。若密文已保存但明文未清理完，程序只重试清理，避免用不完整工作区覆盖完整快照。

当前密文损坏、上一版本完好时：先备份整个目录，再由管理员将上一版本复制为当前版本并尝试解锁。此方式会丢失上一版本之后的修改，不能保证修复所有损坏。

**忘记密码无法恢复。** 软件没有后门或在线找回密码功能。

## 加密实现与安全边界

- AES-256-CBC 加密文件快照；HMAC-SHA256 对数据做完整性认证，先认证完整密文，再解密。
- PBKDF2-HMAC-SHA256 将密码派生为密钥：新建快照使用 600,000 次迭代和随机 32 字节盐，加密密钥与认证密钥分开。
- 每次保存生成新的随机 IV（初始化向量，用于使相同内容的加密结果不同）。
- 保存时先生成新密文，解密并逐文件核对 SHA-256，再替换当前快照。
- 拒绝不安全的归档路径、链接、并发编辑和外部快照变化。

必须理解以下限制：

- **解锁期间有明文。** 同一 Windows 账户可访问编辑区；异常退出后的工作区也可能有明文。
- 明文清理采用普通删除，不承诺清除 SSD 历史块、编辑器缓存、系统备份或其他历史副本。
- 程序运行中需要使用密码和密钥，不承诺清除托管运行时或系统中的全部内存副本。
- NTFS 权限保护针对受支持位置的常规操作。管理员接管权限、更改上级权限、格式化磁盘仍可破坏数据。
- 程序不会自动更改上级目录权限；若上级权限允许绕过保护移动整个目录，则拒绝创建。
- 大文件夹每次锁定重新生成整个快照，耗时与内容大小有关。
- 本项目尚未经过独立安全审计，不宣称绝对安全。

## 生成安装包

另行准备 NSIS 3.13，将下面示例路径替换为自己的 `makensis.exe`：

```powershell
.\scripts\package.ps1 -NsisCompiler 'C:\Tools\NSIS\makensis.exe'
```

若已将 `makensis.exe` 加入 PATH，可省略参数。脚本每次先重新编译仓库源码，再生成：

```text
artifacts/dist/FolderSeal-<版本>-Setup.exe
artifacts/dist/SHA256SUMS.txt
```

可用 `Get-FileHash -Algorithm SHA256` 核对安装包。构建工具和安装包不属于源码同步内容；后续可以单独作为 GitHub Release 附件发布。

生成带中文说明和许可证的便携包：

```powershell
.\scripts\package-portable.ps1
```

输出为 `artifacts/dist/FolderSeal-<版本>-Portable.zip` 和 `PORTABLE-SHA256SUMS.txt`。源码提交、版本标签和 Release 附件的完整流程见[发布流程](docs/发布流程.md)。

安装包仅包含通用程序、使用说明及卸载程序，不附带私人资料或个人启动参数。程序未使用商业代码签名证书，Windows 可能显示“未知发布者”。

卸载只删除程序和快捷方式，保留加密目录与遗留工作区；目录的 NTFS 保护仍存在。重新安装后可使用原密码继续访问。

## 简洁工作台

创建与选择入口仅在左侧。未选择资料时，右侧只显示文件区和空状态；选中资料后以一行显示名称、状态与主操作。解锁后直接导入文件、导入文件夹或打开编辑区。

“更多”提供恢复未锁定工作区、创建或修复密封夹入口、右键菜单设置与删除加密文件夹。文件夹名称悬停可查看完整路径。错误详情可滚动查看、选中复制。锁定后继续隐藏文件名和数量。

## 单窗口运行

再次打开软件会激活已有窗口；再次打开同一已解锁资料的图标入口，会使用原编辑区。当前资料未完成保存锁定、正在处理或有对话框时，不会自动切换资料；先完成当前操作后重新打开目标入口。

安装版和便携版的新版本使用同一实例标识。首次从旧版升级时，请先在所有旧窗口保存并锁定、正常退出；旧版没有单实例机制，不能自动纳入新窗口管理。仍被其他进程占用时，程序会给出明确提示；不要删除锁文件或强制结束正在编辑的进程。

实例间只通过当前用户可访问的本机命名管道转交启动参数，不传输密码，不联网。管理员授权要求保持不变。

## 命令行入口

正常使用无需命令行。以下参数保留现有行为，涉及文件操作时请先使用副本：

| 参数 | 行为 |
| --- | --- |
| 无参数 | 打开主窗口 |
| `--open-vault "<加密目录>"` | 选择该目录，要求输入密码，成功后打开编辑区；图标入口使用此参数 |
| `--move-source "<源文件>"` | 预选单个源文件；用户创建加密目录后，完成加密与核验且源文件未变化才删除源明文 |

密码由用户在界面输入，不接受命令行传入。图标入口、安装标识和密文格式保持原实现。
